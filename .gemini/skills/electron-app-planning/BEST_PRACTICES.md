# Best Practices

This document provides best practices and practical guidelines for successfully planning Electron desktop applications.

## Planning Principles

### Security First

Electron apps have high security risks, so the following must be observed:

#### Required Settings

```javascript
// BrowserWindow settings
const mainWindow = new BrowserWindow({
  webPreferences: {
    nodeIntegration: false,      // Required: Disable Node.js in renderer
    contextIsolation: true,       // Required: Context isolation
    sandbox: true,                // Recommended: Sandboxing
    preload: path.join(__dirname, 'preload.js')
  }
});
```

#### IPC Design Best Practices

```javascript
// preload.js - Safe API exposure
const { contextBridge, ipcRenderer } = require('electron');

contextBridge.exposeInMainWorld('api', {
  // Expose only explicitly defined APIs
  readFile: (filePath) => ipcRenderer.invoke('read-file', filePath),
  saveFile: (filePath, content) => ipcRenderer.invoke('save-file', filePath, content),

  // Event listeners
  onFileChanged: (callback) => {
    ipcRenderer.on('file-changed', (event, ...args) => callback(...args));
  }
});

// main.js - Input validation on the handler side
ipcMain.handle('read-file', async (event, filePath) => {
  // Input validation
  if (typeof filePath !== 'string') {
    throw new Error('Invalid file path');
  }
  // Path traversal protection
  const safePath = path.resolve(allowedDir, path.basename(filePath));
  return fs.readFileSync(safePath, 'utf-8');
});
```

#### What to Avoid
- Using `nodeIntegration: true`
- Using `contextIsolation: false`
- Using the `remote` module (deprecated)
- Loading external content via `loadURL` without validation

### Performance Optimization

#### Main Process

```javascript
// Bad example: Heavy processing in the main process
ipcMain.handle('heavy-task', async () => {
  // This could block the UI
  return heavyComputation();
});

// Good example: Utilizing worker threads
const { Worker } = require('worker_threads');

ipcMain.handle('heavy-task', async () => {
  return new Promise((resolve, reject) => {
    const worker = new Worker('./heavy-worker.js');
    worker.on('message', resolve);
    worker.on('error', reject);
  });
});
```

#### Renderer Process
- Virtualized lists (when displaying large amounts of data)
- Lazy loading images
- Reducing unnecessary DOM operations
- Using memo components in React/Vue or compiled CSS

#### Memory Management
- Destroy unnecessary windows using `destroy()`
- Properly release large objects
- Monitor memory with `process.memoryUsage()`

```javascript
// Cleanup when window is destroyed
mainWindow.on('closed', () => {
  mainWindow = null;
});
```

### Auto-Update Design

```javascript
const { autoUpdater } = require('electron-updater');
const log = require('electron-log');

autoUpdater.logger = log;
autoUpdater.logger.transports.file.level = 'info';

// Check for updates
autoUpdater.checkForUpdatesAndNotify();

// Event handling
autoUpdater.on('checking-for-update', () => {
  log.info('Checking for update...');
});

autoUpdater.on('update-available', (info) => {
  // Update notification UI
  dialog.showMessageBox({
    type: 'info',
    title: 'Update Available',
    message: 'A new version is available. Starting download.'
  });
});

autoUpdater.on('update-downloaded', (info) => {
  // Prompt for restart
  dialog.showMessageBox({
    type: 'info',
    title: 'Update Ready',
    message: 'Restart now to install the update?',
    buttons: ['Restart', 'Later']
  }).then((result) => {
    if (result.response === 0) {
      autoUpdater.quitAndInstall();
    }
  });
});

autoUpdater.on('error', (err) => {
  log.error('Update error:', err);
});
```

## Common Failure Patterns and Mitigation

### Failure Pattern 1: Security Vulnerabilities

**Symptoms**: XSS, Remote Code Execution (RCE) vulnerabilities

**Causes**:
- `nodeIntegration: true`
- `contextIsolation: false`
- Unvalidated input

**Mitigation**:
- Strict security settings
- Input validation
- Content Security Policy (CSP) settings
- Regular dependency updates

### Failure Pattern 2: Performance Issues

**Symptoms**: Slow startup, sluggish behavior, high memory consumption

**Causes**:
- Excessive initialization at startup
- Heavy processing in the main process
- Memory leaks

**Mitigation**:
- Minimize startup processing
- Utilize lazy loading
- Utilize Worker Threads
- Memory profiling

### Failure Pattern 3: Store Review Rejection

**Symptoms**: Cannot publish on Mac App Store / Microsoft Store

**Causes**:
- No sandboxing support
- Guideline violations
- Notarization not performed

**Mitigation**:
- Read each store's guidelines thoroughly
- macOS: Support sandboxing, enable Hardened Runtime
- Windows: Support MSIX format
- Pre-release test builds

### Failure Pattern 4: Cross-Platform Compatibility

**Symptoms**: Doesn't work on specific OS, UI is broken

**Causes**:
- OS-specific path handling
- Font/UI differences
- Permission differences

**Mitigation**:
- Use `path.join()`
- UI testing on all operating systems
- Proper implementation of permission requests

## Points by Planning Phase

### Phase 1: Idea Generation

#### To Do
- Clarify why a desktop app is suitable
- Identify value that cannot be achieved with a Web app
- Research competing desktop apps

#### Avoid
- "Just because" desktop app
- Making features into a desktop app that are sufficient on Web
- Clones without differentiation

### Phase 2: Design

#### To Do
- Security design first
- Detailed IPC design
- Assume behavior on all operating systems

#### Avoid
- Putting off security
- Designing for only one OS
- Excessive features

### Phase 3: Development

#### To Do
- Confirm builds on all OS early
- Security testing
- Performance measurement

#### Avoid
- Developing on only one OS
- Putting off testing
- Neglecting dependencies

### Phase 4: Distribution

#### To Do
- Obtain code signing
- Implement auto-updates
- Collect crash reports

#### Avoid
- Distributing without signing
- Manual updates only
- No error tracking
